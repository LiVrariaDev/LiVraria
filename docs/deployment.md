# デプロイ方針

## 現在の前提

本番公開は Nginx を入口とし、フロントエンドのビルド成果物を配信しながら、API リクエストを FastAPI サーバーへリバースプロキシする構成を前提とする。

Docker Compose は未検証のため、本番デプロイ手順として使用しない。詳細は [Docker の状態](docker.md) を参照する。

## 想定する責務分担

| 要素 | 責務 |
| --- | --- |
| Nginx | TLS 終端、静的ファイル配信、バックエンド API へのリバースプロキシ |
| フロントエンド | `frontend/` でビルドした `dist/` の配信対象 |
| バックエンド | FastAPI アプリケーションの起動、Firebase・LLM・書籍検索 API との連携 |
| 秘密情報 | デプロイ先で `.env` とサービスアカウント鍵を安全に管理し、Git に含めない |

## デプロイ前に確認すること

- `pnpm -C frontend run build` が対象環境または再現可能なビルド環境で成功すること
- `VITE_API_BASE_URL` が公開 URL と一致すること
- `PRODUCTION_ORIGINS` に実際のフロントエンドオリジンを設定すること
- Nginx の API ルーティングと、フロントエンドが要求するパス（`/users`、`/sessions`、`/nfc`、`/search`、`/books`）が整合すること
- FastAPI をどのプロセス管理方式で常駐させるかを決めること
- TLS 証明書の取得・更新方法、ログ出力先、障害時の復旧手順を決めること
- Firebase サービスアカウント鍵、Gemini API キーなどをデプロイ先で安全に渡せること

## 未確認事項

このリポジトリには Nginx の実稼働設定、systemd 等のバックエンド常駐設定、証明書更新手順の検証結果がない。上記を確認するまで、コピーして実行できる本番手順や設定例は掲載しない。

また、Raspberry Pi/NFC サーバーを本番公開構成のどこに配置するか、Nginx 経由で到達させるかは未確定である。
