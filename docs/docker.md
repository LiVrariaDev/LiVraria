# Docker の状態

## 結論

Docker Compose と Dockerfile はリポジトリに残っているが、現行構成でのビルド・起動・運用は確認されていない。そのため Docker は開発・本番ともに非推奨、かつサポート対象外とする。

`docker-compose.yml`、`backend/Dockerfile`、`frontend/Dockerfile` は削除していない。将来 Docker を再採用する場合の比較材料として保持する。

## 通常手順から外す理由

- Compose 構成が現在の `.env`、Firebase サービスアカウント鍵、フロントエンド API 接続設定と整合することを確認していない。
- フロントエンドからバックエンドへの通信、CORS、Nginx との役割分担をコンテナ構成で確認していない。
- JSON データストアの永続化と、再起動時の扱いを Compose に定義していない。
- Docker での起動を CI や実機で継続的に検証していない。

## 再構築する場合の受入条件

Docker を再び案内・採用する場合、対象は本番環境とする。別タスクで少なくとも以下を確認する。

1. フロントエンドとバックエンドのイメージを再現可能にビルドできる。
2. 秘密情報をイメージへ焼き込まず、`.env` とサービスアカウント鍵を安全に渡せる。
3. ブラウザから認証済み API、書籍検索、必要な外部 API へ到達できる。
4. JSON データの保存先と、再作成・再起動時の挙動を決められる。
5. Nginx を使う本番構成との責務分担、TLS、公開ポートを文書化できる。
6. 本番環境で起動確認を行い、Nginx と連携した公開経路を検証する。

これらを満たすまで、Docker コマンドを README やデプロイ手順に掲載しない。
